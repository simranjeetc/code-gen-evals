Plain-English walkthrough

We built a fair test for robot coders

Give four AI models the same homework, grade each answer four different ways, and report where the grades disagree.

The sharpest framing: this isn't "rate a robot's coding ability" — plenty of benchmarks do that. It's map where that ability stops. The rating is the byproduct; the failure map is the product. One score of "it passed" is like a driving test that only checks parking.

What it is, in four parts

📄 20 homework puzzles

Easy (FizzBuzz) to hard (a thread-safe counter). Each has a verified correct answer, so we can check.

🤖 5 robots

Four via the OpenCode subscription, one via Claude Code. Same puzzles, same conditions: no tools, temperature 0.

📊 4 grades per answer

Did it run? Handle weird inputs? Do what we meant? Is it tidy? Four different questions, four separate scores.

📝 An honest report

When the grades disagree, it says so instead of averaging them into one tidy lie.

There's also a cardboard robot. A fake model with no AI in it, so the machinery can be tested with no internet and no cost. It says nothing about any real robot — a development convenience, not a feature.

The four grades

One answer, four separate judges. The whole point is that they can disagree.

Why two test sets, and who judges?

Only the question is sent to the robot. Neither test set is ever sent — they're hidden from the model, not secret from you. Both are in the repo for anyone to read.

Two sets exist because one can't tell "solved it" from "satisfied the exact assertions we happened to write". Work asks the ordinary question; survive asks what happens on inputs nobody showed it.

The judge is a different model (Claude judges DeepSeek, not itself). The code refuses self-grading outright — if judge and subject are the same model, the judge abstains rather than score itself.

What happens when you press go

The repeat is the only complicated part.

The clever bit: when the grades fight

Averaging them into one number would lose the most useful information.

Real example

Passed every test… but missed the point

A robot's rate_limiter scored 1.00 with our tests, but the judge said 0.50 — not quite what you asked for. Both are true. Our tests were too easy; the judge caught it.

Real example

Works fine, but it's a mess

The same answer scored 1.00 for working and 1.00 for understanding, but only 0.60 for tidiness — no labels, no notes. Correct code a human would groan at.

Why it matters: shown only 0.87 vs 0.85 you might pick the wrong robot. Told one is tidier and the other handles weird inputs better, you can pick for your situation.

The honest part, and it matters more than the table. Sonnet cleared every test on every puzzle, including the five I wrote specifically to separate models. The only place it visibly loses points is tidiness. Either these puzzles are still too easy, or the robots are all genuinely good at them — and one run can't tell you which.

That ambiguity is the point of the tool, not a failure of it. It says "these grades disagree" rather than inventing a winner. The next step is the control experiment below, not more robots.

The safety net that caught our own mistake

A rule that refuses to give a fake answer.

"If every robot scores exactly the same on every question, say the test failed — don't pretend you ranked them."

It fired twice while building. Once it caught a real bug: a run where every score was silently blank because of a mistake in our own code, and all the robots "looked" identical. The net refused to report it. 

normal run  →  here are your scores
all identical  →  INCONCLUSIVE
                    saved, but flagged

Where it stands

Done, and not done — read the right column carefully.

✓ Done and proven

  • • 20 puzzles, verified answers — 40 checks, all pass
  • • Four grades working, judge included
  • • 5 robots: 4 OpenCode + Claude Code
  • • Report rebuilds offline from saved scores
  • • 208 tests; quickstart 37s from scratch
  • • Committed to git (3 commits)

! Known weaknesses

  • • Robots still tie. All clear the hard puzzles. Ranking rests on tidiness alone.
  • • 20 puzzles is a small sample, and the original 15 are famous — memorisation isn't ruled out.
  • • The judge is an AI. It's forced to be a different model, but still an AI.
  • • Robot code runs with no sandbox. Only the cardboard robot is safe.
  • • Only the OpenCode bank is broad; a wider bank is untested.

What I'd refuse to publish today

The current numbers are 0.90–1.00 across five near-identical robots, on puzzles that can't discriminate. Published as-is it invites ranking models on noise — and a benchmark that looks authoritative and measures nothing is worse than none, because people quote the numbers.

This isn't a product yet. It's a measurement instrument you built for yourself, and instruments get published once they produce a repeatable reading.

If it becomes a public thing

Lead with the negative result: "my benchmark failed to measure anything and I published it anyway." That's the scarcest thing in this space, and it makes everything else believable.

Best fit commercially: custom evals for a company's own codebase — their tasks, their repo, a report. You're not selling software; you're selling the ability to answer a question.
